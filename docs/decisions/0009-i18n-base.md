# ADR 0009 — Base de internacionalização (i18n)

- **Status:** Proposta (29/09/2026) — aguardando aprovação na etapa 7 da Fase 0

## Contexto

O PROJECT_SPEC (seção 3.3) define três níveis de tradução: interface, conteúdo e formatos.
Esta etapa monta o nível **interface** para `pt-BR`, `en` e `es` (ADR 0004) no app e no painel.
Os formatos (`Intl`) já existiam desde a etapa 5; o conteúdo fica para a Fase 1 (banco).

## Decisão

1. **i18next 26** em `@gfg/i18n`, sem plugins de carregamento: os três arquivos JSON vão
   junto no código (são pequenos) e a inicialização é síncrona (`initAsync: false`).
2. **Arquivos em `packages/i18n/locales/`** (`pt-BR.json`, `en.json`, `es.json`), um só
   namespace (`translation`) com grupos `common.*`, `mobile.*` e `admin.*`.
3. **`pt-BR.json` é a referência.** Um tipo gerado a partir dele faz o TypeScript recusar
   chaves inexistentes em `t('...')` no app e no painel.
4. **Fallback em inglês** (`en`), como definido na ADR 0004.
5. **Plural pelas regras oficiais (`Intl.PluralRules`)**: `pt-BR` e `es` têm as formas
   `one`, `many` e `other`; `en` tem `one` e `other`.
6. **Testes de consistência** (`resources.test.ts`): mesmas chaves nos três idiomas, nenhum
   texto vazio, mesmas variáveis `{{...}}` e todas as formas de plural de cada idioma.
7. **App mobile:** `react-i18next` (`I18nextProvider` + `useTranslation`) e
   **`expo-localization`** (~57.0.2, incluído no Expo Go) para ler a lista de idiomas
   preferidos do aparelho — substitui a leitura via `Intl` da etapa 5 (ADR 0007, item 8).
8. **Painel admin:** traduz no servidor com `getTranslator()`, sem `react-i18next`.
   Componentes de cliente (menu lateral) recebem os textos prontos por props.
   Idioma definido por **`ADMIN_LOCALE`** (padrão `pt-BR`), já que a equipe de conteúdo
   trabalha em português; a escolha por usuário virá com o login real.
9. `apps/admin/src/config/site.ts` foi removido: o nome do app e do painel agora vêm das traduções.

## Consequências

- Nenhum texto da interface fica fixo no código das telas; adicionar um idioma exige só um
  novo JSON e o código do idioma em `@gfg/core` (ADR 0004).
- A troca de idioma dentro do app (perfil do usuário) é feita com `i18n.changeLanguage()`
  quando o perfil existir (Fase 1).
- Quando os arquivos crescerem, dá para separar por namespace ou carregar sob demanda sem
  mudar as chamadas `t('...')`.
